## 1. 产品概述

### 1.1 背景

面向住院患者家属，提供院内陪护服务的在线预约入口。用户领取服务券后，在 H5 内填写护理人、住院信息、期望服务时间和照护需求，提交后由照护顾问审核评估并安排护理员到院服务。

### 1.2 产品目标

1. 家属可独立完成院内照护预约，不依赖线下表单。
2. 服务券状态、订单状态、服务进度对用户透明。
3. 预约信息结构清晰，适老化阅读。
4. 与供应商易得康的卡、服务记录、客户信息接口保持字段可映射。

### 1.3 产品边界

- 本版本不包含支付、价格、费用、优惠券购买。
- 不展示“服务卡”概念，C 端统一使用“服务券”。
- 不做护理员抢单、打卡、服务记录填写；这些由运营/供应商侧完成。
- 登录、券、订单目前为前端演示数据，正式上线需接后端。

## 2. 用户与角色

| 角色 | 说明 | 主要操作 |
|---|---|---|
| 家属用户 | 住院患者的家属，预约服务的人 | 登录、预约、查看订单、取消/修改预约、查看券包 |
| 护理人 | 实际接受院内照护的人 | 由家属填写实名信息，不直接使用 H5 |
| 联系人 | 对接照护顾问的人 | 接收顾问电话，默认是下单家属 |
| 照护顾问 | 平台运营人员 | 审核评估、电话确认、安排护理员 |
| 护理员 | 到院提供服务的人 | 接单、到院签到、提供服务 |
| 易得康 | 服务卡/服务记录供应商 | 提供卡同步、服务记录申请、客户信息更新接口 |

## 4. 全局交互与规则

### 4.1 登录规则

- 手机号：任意 11 位数字。
- 验证码：任意 6 位数字。
- 不做真实短信校验，不做手机号归属地校验。
- 首次登录自动创建账户。
- 登录成功后进入“服务预约”。
- 登录页协议默认不勾选，必须勾选后才能登录。

### 4.2 导航规则

- 登录后常驻底部 Tabbar：**服务预约 / 我的**。
- 服务预约、我的、订单列表、订单详情显示 Tabbar。
- 卡券、隐私政策等二级页不显示 Tabbar，使用左上角返回。
- 页面顶部为 iOS 风格标题栏：
  - 服务预约：标题“服务预约”，无返回。
  - 我的：标题“我的”，无返回。
  - 我的订单、订单详情、卡券：标题 + 左上角返回。
- 主按钮、Tab 选中态使用医院十字标志蓝 `#2E6BFF`。

### 4.3 时间格式

| 场景 | 格式 | 示例 |
|---|---|---|
| 预约时间 / 期望时间 | `YYYY.MM.DD HH:mm` | `2026.11.18 09:00` |
| 出生日期 | `YYYY.MM.DD` | `1948.03.12` |
| 订单进度时间 | `MM-DD HH:mm:ss` | `11-17 15:12:52` |
| 更新时间 / 下单时间 / 服务完成时间 | `YYYY-MM-DD HH:mm:ss` | `2026-11-17 15:12:52` |
| 服务券有效期 | `YYYY.MM.DD – YYYY.MM.DD` | `2026.01.01 – 2027.06.30` |

> 除预约时间和出生日期外，订单相关时间均精确到秒。

### 4.4 服务券规则

- 服务券为**单次使用券**，每次提交预约消耗 1 张。
- 可用次数 = 券包中“未使用”券的数量。
- 卡券号完整展示，不掩码。
- 卡券界面只展示一次“单次使用”，不重复出现“单次服务券”。
- 每张券展示：产品名、完整券号、有效期起止、状态、使用人。
- 提交预约：
  - 从未使用券中自动选择 1 张。
  - 该券立即变为“已使用”，并关联订单。
- 取消预约：
  - 订单取消后，该订单占用的服务券自动返还为“未使用”。
- 修改预约：
  - 沿用原预约已占用的服务券，不额外消耗新券。
- 重新预约：
  - 使用新的未使用券；没有可用券时跳转券包并提示。

### 4.5 订单状态

| 系统状态 | 用户展示状态 | 说明 |
|---|---|---|
| `pending` | 待确认 | 申请已提交，等待顾问审核评估 |
| `accepted` | 已预约 | 顾问已确认，已安排护理员 |
| `serving` | 服务中 | 护理员已到院，服务进行中 |
| `completed` | 已完成 | 服务结束，家属确认完成 |
| `cancelled` | 已取消 | 用户取消预约 |

### 4.6 状态与进度映射

| 订单状态 | 状态标题 | 进度时间轴展示 |
|---|---|---|
| 待确认 | 预约待确认 | 仅“服务申请已提交” |
| 已预约 | 预约已确认 | 提交 → 评估完成/安排护理员 |
| 服务中 | 服务进行中 | 提交 → 评估完成/安排护理员 → 服务开始 |
| 已完成 | 本次陪护已完成 | 提交 → 评估完成/安排护理员 → 服务开始 → 服务完成 |
| 已取消 | 预约已取消 | 保留已发生节点，并追加“服务申请已取消” |

### 4.7 全局反馈

- 所有保存、提交、复制、取消等操作使用 Toast 提示。
- 关键操作（取消预约、退出登录）使用底部确认弹层。
- 表单错误使用字段下方红色提示，并自动滚动到第一个错误字段。
- 空状态必须提供明确下一步按钮。

## 5. 页面需求

## 5.1 登录注册

### 5.1.1 页面目标

让用户用手机号快速进入服务预约，不设置密码，不强制注册流程。

### 5.1.2 页面布局

从上到下：

1. 顶部返回按钮 + 标题“登录注册”。
2. “Hello!” + “欢迎使用” + 医疗盾牌插画。
3. 白色圆角登录面板。
4. 手机号输入框。
5. 验证码输入框 + 获取验证码。
6. 登录按钮。
7. 协议勾选。

### 5.1.3 展示信息

| 元素 | 文案 |
|---|---|
| 页面标题 | 登录注册 |
| 主标题 | Hello! |
| 副标题 | 欢迎使用 |
| 手机号 Label | 手机号 |
| 手机号 Placeholder | 请输入手机号 |
| 验证码 Label | 验证码 |
| 验证码 Placeholder | 请输入验证码 |
| 获取验证码 | 获取验证码 |
| 登录按钮 | 登录 |
| 协议 | 我已阅读并同意《用户服务协议》和《用户隐私协议》 |
| 底部品牌 | 安颐院内照护 · 专业陪护服务 |

### 5.1.4 交互

1. 输入手机号：
   - 仅允许数字，最多 11 位。
2. 点击“获取验证码”：
   - 未输入 11 位：Toast“请输入 11 位手机号”。
   - 成功：按钮进入 60 秒倒计时，显示“59s 后重试”。
   - Toast“验证码已发送，输入任意 6 位数字即可登录”。
3. 勾选协议：
   - 点击整行切换勾选态。
4. 点击“登录”：
   - 手机号不是 11 位数字：Toast“请输入 11 位手机号”。
   - 验证码不是 6 位数字：Toast“请输入 6 位验证码”。
   - 未勾选协议：Toast“请先阅读并同意用户服务协议与隐私协议”。
   - 全部通过：写入登录态，进入服务预约。
5. 返回按钮：
   - 有历史记录则返回；无历史记录 Toast“请先登录”。

### 5.1.5 异常与边界

- 不校验手机号真实归属。
- 不校验验证码正确性。
- 刷新后如已登录，直接进入服务预约。

## 5.2 服务预约

### 5.2.1 页面目标

在一个页面内完成服务券确认、护理人信息、住院信息、期望时间、照护需求、联系人信息填写，并提交预约。

### 5.2.2 页面结构

从上到下：

1. iOS 标题栏“服务预约”。
2. 浅蓝渐变头图：
   - 彩色渐变标题“院内照护预约”。
   - 副文案“填写信息并提交预约，照护顾问将审核评估后确认服务安排。”
   - 右侧医院建筑图案（透明背景，与渐变融合）。
3. 进行中提示（有进行中订单时）。
4. 卡券。
5. 填写护理人信息。
6. 填写住院信息。
7. 期望服务时间。
8. 照护需求。
9. 填写联系人信息。
10. 协议与提交栏。
11. 底部 Tabbar。

### 5.2.3 进行中提示

您有 {N} 个进行中预约，另有 {M} 张服务券可用，可继续提交新的预约。

### 5.2.6 填写住院信息

| 字段 | 控件 | 必填 | 规则 |

- 不采集住院号、床号。
- 切换城市后，医院列表联动刷新。

文案：

- 右侧：用于匹配院内护理员

### 5.2.7 期望服务时间

- 快捷日期：今天 / 明天 / 后天。
- 日期时间控件：`YYYY/MM/DD HH:mm`。
- 必填，最小值为今天。
- 不选择服务项目，不选择服务时长。

文案：

- 标题：期望服务时间
- 右侧：照护顾问将评估确认
- Label：期望服务时间

### 5.2.8 照护需求

- 多选，至少选择 1 项。
- 选项：术后照护、翻身叩背、助餐喂食、如厕助洁、夜间看护、陪检陪护、康复协助、压疮护理、管路护理、失智照护。
- 右侧显示“已选 N 项”。
- 补充说明选填，Placeholder：
  “例如：术后不能下床、夜间需要协助起夜、饮食禁忌等”。

### 5.2.9 填写联系人信息

| 字段 | 控件 | 必填 | 规则 |
|---|---|---|---|
| 姓名 | 文本输入 | 是 | 不能为空 |
| 手机号 | 电话输入 | 是 | 11 位，1 开头 |

- 不采集联系人证件。
- 不采集紧急联系人、紧急联系电话。

文案：

- 标题：填写联系人信息
- 右侧：用于顾问确认

### 5.2.10 协议与提交

协议：

```text
我已阅读并同意《院内照护服务协议》与《隐私政策》，确认住院信息与照护需求真实有效
```

服务说明：

```text
服务由持证护理员提供，到院签到、护理记录全程可追溯
```

底部操作栏：

```text
提交后照护顾问将审核评估
确认服务安排后与您联系
[提交预约]
```

- 操作栏固定在 Tabbar 上方。
- 默认隐藏，页面滚动到底部后显示。
- 修改预约时按钮文案为“保存修改”。

### 5.2.11 提交校验

提交时依次校验：

1. 有可用服务券。
2. 城市、医院、科室、入院疾病必填。
3. 期望服务时间必填且不早于今天。
4. 护理人姓名、性别、出生日期、证件号必填。
5. 身份证号格式正确。
6. 联系人姓名、手机号必填。
7. 至少选择 1 项照护需求。
8. 已勾选协议。

失败：

- 字段标红并显示错误文案。
- 滚动到第一个错误字段。
- Toast“请补充带 * 的必填信息”。

成功：

- 消耗 1 张服务券。
- 生成“待确认”订单。
- 进入订单详情。
- Toast“服务申请已提交，照护顾问将评估安排”。

### 5.2.12 修改预约

- 入口：订单列表/订单详情“修改预约”。
- 页面标题变为“修改预约”。
- 副文案“修改后预约将重新进入待确认状态。”
- 表单预填原订单信息。
- 沿用原服务券，不消耗新券。
- 保存后：
  - 状态回到待确认。
  - 追加进度“服务申请已修改 / 修改后的服务申请等待照护顾问评估确认”。
  - Toast“服务申请已修改，等待评估确认”。

## 10. 验收标准

1. 任意 11 位手机号 + 任意 6 位验证码可登录。

7. 提交后生成待确认订单，服务券变为已使用。

9. 我的页面展示四项统计，包含服务中数量。
10. 订单列表包含服务中分类，卡片三项信息单行展示。

15. 取消预约返还服务券；修改预约不重复扣券。
