# 易得康接口对应的客户信息页面设计

> 依据：《易得康 API 接口技术文档》  
> 涉及接口：卡同步通知、激活数据同步、服务记录申请、客户信息更新  
> 适用页面：服务预约、我的、预约详情、客户信息

> **2026-11-17 UI 更新**：C 端不展示“卡”，统一使用“服务券”；供应商接口中的 `cardNum`、`cardType`、`productCode` 由服务券在内部映射。页面收敛为「服务预约 / 我的」两个 Tab，不再提供卡管理页。服务券为单次使用券，可用次数 = 券包未使用券张数；每笔预约消耗 1 张，取消预约返还。
>
> **表单最终字段与顺序**：卡券 → 护理人姓名/性别/出生日期/证件类型/证件号 → 住院信息（城市、医院、科室、入院疾病/诊断、住院日期选填）→ 预约时间 → 照护需求 → 联系人姓名/手机号。不含住院号、床号、护理人手机号、省市区地址、自理能力、紧急联系人。券号完整展示，不做掩码。

---

## 一、先给结论

接口文档把“客户信息”拆成了 **三类人 + 一张卡 + 一个订单**，页面不能只用一个“患者信息”表单承载：

| 对象 | 业务含义 | 主要来源 | 页面处理 |
|---|---|---|---|
| 持卡人 / 被保障人 `mainInsurer` | 服务卡的被保险人 | 激活数据同步 | 展示为主，激活时收集 |
| 护理对象 / 客户 `leaguer / consumer` | 实际接受院内陪护的人 | 服务申请、客户信息更新 | 申请时收集，可维护默认档案 |
| 联系人 `cus` | 下单、对接、接收服务通知的人 | 服务申请、客户信息更新 | 申请时收集，默认取登录账户 |
| 服务卡 `card` | 单次卡 / 钻石卡 / 家庭卡 | 卡同步、激活 | 申请前必须选定有效卡 |
| 订单 `reserveOrderNo` | 本次服务申请 | 我方生成 | 提交时同步给易得康 |

**当前院内 H5 表单缺少的接口必填项：**

1. 服务卡：卡号、卡类型、产品编码、产品名称
2. 护理对象：证件类型、证件号、出生日期
3. 服务地点：城市、医院编码（当前只有医院名称）
4. 住院信息：入院疾病
5. 客户信息更新：护理对象手机号、省/市/区/详细地址、联系人证件信息
6. 持卡人激活信息（若需要在本页面激活卡）

## 二、推荐页面结构

```text
登录注册（手机号 + 任意 6 位验证码）
  ↓
Tab 1：服务预约
  ├─ 服务券（自动使用，内部映射供应商卡字段）
  ├─ 预约机构与住院信息
  ├─ 选择预约项目
  ├─ 预约时间（7 天日期滑动）
  ├─ 就诊人信息
  ├─ 照护需求（内部运营字段）
  └─ 确认授权 → 提交
        ↓
     预约详情（含易得康同步状态）

Tab 2：我的
  ├─ 预约列表（全部 / 待确认 / 已预约 / 已完成 / 已取消）
  ├─ 预约详情（查看 / 取消 / 修改 / 重新预约）
  ├─ 客户信息（默认护理对象/联系人/地址）
  ├─ 账户信息
  ├─ 隐私政策
  └─ 退出登录
```

> 服务券由后台发放，C 端不展示卡号管理、激活码或选卡入口；服务券可用状态由卡同步数据在内部判断。

> 不建议把“选卡”做成登录后的强制拦截页。登录后仍直接进入申请页，在表单顶部放服务卡选择器；没有可用卡时，在卡片位置引导激活或联系客服。

## 三、页面一：院内照护申请页

### 3.1 服务卡与权益（表单顶部）

**展示（只读）**

| 字段 | 展示说明 | 接口字段 |
|---|---|---|
| 卡号 | 默认脱敏，详情可查看 | `cardNum` |
| 卡类型 | 单次卡 / 钻石卡（不限次）/ 家庭卡 A / 家庭卡 B | `cardType`（120/121/122/123） |
| 产品名称 | 如“太平洋保险-照护无忧卡” | `productName`（服务申请） |
| 产品编码 | 如 `FS2021036` | `productCode` |
| 使用年限 | 文档字段 `dueline`，需确认是年限还是截止日期 | `dueline` |
| 服务起止 | 服务有效期 | `startTime` / `endTime` |
| 持卡人 | 姓名 + 脱敏证件号 | `mainInsurerName` / 证件字段 |
| 卡状态 | 未激活 / 正常 / 已删除 / 已过期 | `status`（0 添加，1 删除）+ 本地有效期判断 |

**操作**

- 切换服务卡
- 查看权益详情
- 去激活（无卡或未激活）
- 联系客服

**激活时收集**

| 字段 | 必填 | 校验 | 接口字段 |
|---|---|---|---|
| 卡号 | 是 | 与卡同步数据一致 | `cardNum` |
| 激活码 | 否 | 按供应商规则 | `activationCode` |
| 卡类型 | 是 | 120/121/122/123 | `cardType` |
| 产品编码 | 是 | 产品映射表 | `productCode` |
| 持卡人姓名 | 是 | 2–30 字 | `mainInsurerName` |
| 年龄 | 是 | 0–120，可由出生日期计算 | `age` |
| 证件类型 | 是 | 字典 1–15 | 文档字段疑似 `mainInsurerNameIdType`，需确认 |
| 证件号 | 是 | 身份证校验；其他按类型 | `mainInsurerIdcardno` |
| 手机号 | 是 | 11 位手机号 | `mainInsurerPhone` |
| 常驻地 | 是 | 省/市/区 + 详细地址 | `address` |
| 服务起期 | 是 | 不早于今天 | `startTime` |
| 服务止期 | 是 | 晚于起期 | `endTime` |

> 如果服务卡由保司/上游系统统一激活，则本页只展示、不提供激活入口；需要供应商确认激活责任方。

### 3.2 住院信息

| 字段 | 展示/收集 | 必填 | 规则 | 接口字段 |
|---|---|---|---|---|
| 就诊医院 | 收集 | 是 | 选择医院；必须映射 `hospitalCode` | `hospitalCode` |
| 城市 | 自动/收集 | 是 | 默认取医院所在城市；接口只要求城市 | `city` |
| 科室/病区 | 收集 | 是 | 选择或输入；传科室名称 | `department` |
| 住院日期 | 收集 | 否 | 日期，不晚于今天 | `hospitalizedTime` |
| 入院疾病 | 收集 | 是 | 文本，2–100 字；与“照护需求”区分 | `disease` |
| 床号 | 收集 | 否 | 内部运营用，不传接口 | — |
| 住院号 | 收集 | 否 | 内部运营用，不传接口 | — |

**UI 建议**

- 医院选择后，下方自动带出“城市 + 医院编码已匹配”的只读提示。
- 医院没有 `hospitalCode` 映射时，禁止提交，并提示“该医院暂未开通易得康服务”。
- “入院疾病”用单独输入框/文本域，不要和“照护需求”混在一起。

### 3.3 护理对象（客户）

| 字段 | 展示/收集 | 必填 | 规则 | 接口字段 |
|---|---|---|---|---|
| 姓名 | 收集 | 是 | 2–30 字 | `leaguerName` / `consumerName` |
| 性别 | 收集 | 是 | 男/女/不详 → 1/2/3 | `leaguerSex` / `consumerGender` |
| 证件类型 | 收集 | 是 | 字典 1–15 | `leaguerIdtype` / `consumerIdType` |
| 证件号 | 收集 | 是 | 身份证校验；其他类型格式校验 | `identityNum` / `consumerIdNo` |
| 出生日期 | 收集/自动 | 是 | 身份证可自动解析；用于 `birthday` 和计算年龄 | `birthday` |
| 手机号 | 收集 | 否 | 11 位手机号 | `consumerMobile` |
| 省 | 收集 | 否 | 省/直辖市 | `consumerProvince` |
| 市 | 收集/自动 | 是 | 与医院城市或常住城市一致 | `consumerCity` / `city` |
| 区/县 | 收集 | 否 | 区县 | `consumerCounty` |
| 详细地址 | 收集 | 否 | 街道、门牌 | `consumerAddress` |

**交互**

- 输入 18 位身份证后，自动解析出生日期、性别，并回填；用户可修改出生日期（以证件为准时置灰）。
- 默认带出“常用护理对象”，支持“本次修改不保存为默认”。
- 身份证号、手机号在列表/详情默认脱敏，编辑时再显示完整值。

### 3.4 联系人

| 字段 | 展示/收集 | 必填 | 规则 | 接口字段 |
|---|---|---|---|---|
| 联系人姓名 | 收集 | 是（页面） | 默认取登录账户姓名 | `cusName` |
| 联系人手机号 | 收集 | 是 | 11 位手机号，接收服务通知 | `contactTel` / `cusMobile` |
| 联系人证件类型 | 收集 | 否 | 字典 1–15 | `cusIdType` |
| 联系人证件号 | 收集 | 否 | 按类型校验 | `cusIdNo` |

> 接口里 `cusName`、`cusIdType`、`cusIdNo` 为选填，但页面建议姓名和手机号必填；手机号是 `cusMobile` 的必填项。

### 3.5 照护需求（内部运营字段）

这些字段用于护理员匹配和履约，**接口中没有对应字段**，不要标注为“同步易得康”：

| 字段 | 必填 | 说明 |
|---|---|---|
| 服务类型 | 是 | 24 小时 / 12 小时白班 / 12 小时夜班 / 按次 |
| 开始日期、到院时间 | 是 | 服务安排 |
| 陪护天数 | 是 | 1–30 天 |
| 自理能力 | 是 | 自理 / 半自理 / 不能自理 / 术后卧床 |
| 照护需求 | 是 | 术后照护、翻身叩背、助餐喂食等多选 |
| 补充说明 | 否 | 映射接口 `contxet`（文档疑似拼写错误） |
| 紧急联系人 | 否 | 内部运营用，不传接口 |

### 3.6 确认与授权

提交前展示：

- 服务卡：卡号（脱敏）、卡类型、产品、服务有效期
- 医院、城市、科室、入院疾病
- 护理对象：姓名、性别、证件类型/号码（脱敏）、出生日期
- 联系人：姓名、手机号
- 照护需求：服务类型、时间、天数、需求标签
- 勾选《院内照护服务协议》《隐私政策》《个人信息授权书》

### 6.1 默认档案

| 区块 | 字段 |
|---|---|
| 联系人 | 姓名、手机号、证件类型、证件号 |
| 护理对象 | 姓名、性别、证件类型、证件号、出生日期、手机号 |

### 6.2 更新逻辑

供应商的“客户信息更新”接口必须带 `orderNo + cardNum`，因此**不能只做全局客户资料保存**：

1. 保存为默认档案（本地）。
2. 若存在进行中的订单，弹出“同步到订单”选择：
   - 当前订单
   - 全部进行中订单
3. 对每个订单调用更新接口。
4. 没有订单时，仅保存默认档案，下次申请时带出。

### 6.3 展示要求

- 证件号、手机号默认脱敏
- 修改证件号需二次确认
- 展示“最后同步时间/同步状态”
- 提供“同步到进行中订单”入口

## 九、校验、异常与合规

### 9.1 提交前阻断

- 无有效服务卡（未激活、已删除、已过期、未生效）
- `hospitalCode` 未映射
- 城市为空
- 入院疾病为空
- 护理对象证件类型/证件号/出生日期为空
- 联系人手机号为空
- 卡片服务期不覆盖本次服务日期

### 9.2 接口结果处理

- 仅 `status = 0 && code = 0000` 视为成功
- `status = 0 && code != 0000` 视为失败
- `status = 1` 视为失败
- 失败时保留本地订单，展示“待同步/同步失败”，可重试
- `reserveOrderNo` 做幂等键，防止重复提交

### 9.3 合规

- 身份证、手机号、卡号、地址、疾病均属敏感信息，列表默认脱敏
- 前端只展示，不持有 `accessKey` / `accessSecret`
- 签名、AES 加密、接口调用全部由后端代理
- 日志、埋点、错误上报不得记录完整证件号/卡号/手机号
- 收集前展示授权书，明确“同步至易得康用于服务履约”
